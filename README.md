# ОТП Мания

Корпоративная платформа признания сотрудников: прототип команды для кейс-чемпионата.
Все люди и данные вымышлены.

## Режимы

- **Демо-песочница**: демо-входы на странице входа, данные только в браузере.
- **Рабочий режим**: регистрация по почте и общая база Supabase. Как подключить: [SETUP.md](SETUP.md).

Сайт: https://artem670.github.io/otp-mania/

## Как открыть

`dist/otp-mania.html` — готовое приложение в одном файле. Откройте его в браузере.
Демо-вход доступен для трёх ролей прямо на странице входа (пароль у всех: `demo`):

| Роль | Почта |
|---|---|
| Сотрудник | a.smirnov@mania.demo |
| Руководитель | i.belova@mania.demo |
| Администратор | s.yusupova@mania.demo |

Роль можно переключить в меню аватара. Там же есть «Сбросить демо-данные».

## Стек

React 19, TypeScript, иконки Lucide (через `react-icons/lu`), собственные SVG-графики, собственная дизайн-система на CSS-переменных.
Сборка: esbuild (`node build.mjs`) в один HTML-файл.

В среде разработки не было доступа к npm-реестру, поэтому Vite, Tailwind и Recharts не подключены.
Код совместим с переносом на Vite: точка входа `src/main.tsx`, стили `src/styles.css`, графики изолированы в `src/components/charts.tsx`.

## Архитектура

```
supabase/schema.sql  таблица, правила доступа, защита ролей, письма-уведомления
src/
  data/
    types.ts       модель данных (пользователи, начисления, конвертации, заказы, сборы, настройки…)
    seed.ts        демо-данные: 38 сотрудников, 6 подразделений, 5 руководителей, 1 администратор, 8 месяцев истории
    store.ts       единое хранилище: демо (localStorage) или общая база Supabase + хук useDB()
    remote.ts      клиент Supabase без SDK: вход по почте и таблица docs
    api.ts         ЕДИНСТВЕННЫЙ слой изменений: асинхронные методы с валидацией и бизнес-правилами
    selectors.ts   производные метрики: рейтинг, KPI руководителя, аналитика, сигналы
  components/      дизайн-система (ui.tsx), каркас (layout.tsx), графики, иконки
  pages/
    employee/      профиль и конвертация, магазин, корзина, заказы, благодарности, рейтинг, сборы, питомец
    manager/       начисление РуКоинов, KPI, регламент, сборы команды
    admin/         дашборд, сигналы, сотрудники и роли, настройки программы
    portal/        новости, мероприятия, сотрудники, стратегия, база знаний
```

Все разделы читают одни и те же данные через `useDB()` и `selectors.ts`, поэтому одно и то же число
не может отличаться в разных разделах. Чтобы подключить настоящий бэкенд, заменяются тела методов в
`api.ts` (на HTTP-запросы) и загрузка в `store.ts`. Интерфейс уже асинхронный.

## Ролевая модель

- Сотрудник: кабинет сотрудника.
- Руководитель: всё, что у сотрудника + «Кабинет руководителя».
- Администратор: всё, что у сотрудника + «Администрирование».

Доступ проверяется и в интерфейсе (меню, маршруты), и в `api.ts`.

## Ключевые правила

- KPI руководителя = 40% выполнение плана (без бонуса за перевыполнение) + 30% охват команды + 30% равномерность (1 − индекс Джини).
- Лимиты начисления: за раз, на сотрудника в месяц, квартальный фонд руководителя; обязательный содержательный комментарий.
- Курс конвертации, лимиты, бюджет, категории, товары, заказы и сборы настраиваются администратором.
- Сигналы (частые начисления, концентрация, взаимные благодарности, конец периода, резкий рост, одинаковые суммы,
  без обоснования, превышение лимита, неиспользованный фонд) уходят на проверку со статусами и не считаются нарушением автоматически.
